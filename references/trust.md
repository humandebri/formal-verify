# Trust and verdict policy
- Freeze property and preconditions; record source hashes, tool versions, commands, dependency lockfiles and model-to-code mapping. Review trusted code and imported axioms. Evidence hashes detect changes but do not authenticate authorship.
- Check assumptions are satisfiable; exercise reachable initial states, relevant branches and assertions; add positive and negative controls. Mutation detection is evidence, not completeness.
- PROVED means the exact property follows under listed assumptions, with no unresolved proof obligations and reviewed trust boundary. BOUNDED_SAFE requires explicit bound and completed checking. TESTED is sampling only. COUNTEREXAMPLE needs a validated witness; if it fails replay, investigate MODEL_MISMATCH. UNKNOWN includes incomplete proof, unreviewed logs and inconclusive solver results.
- Never accept Lean sorry/admit or unreviewed axioms; inspect #print axioms for each claimed theorem and its dependencies. Inspect unsafe/native evaluation trust and imported code. Verus: review assume, admit, external_body, external specs, trusted functions, skipped verification, spec/exec differences and preconditions. Kani: review assumptions, stubs, unwinding checks, unsupported operations and harness selection. Quint: review init, step, invariant, bounds, fairness and abstraction. SMT: ensure assumptions alone SAT, then assumptions AND NOT property UNSAT; match language overflow, signedness, division and undefined behavior.
- Static lexical scans are advisory only, not sound proof audits. Do not interpret successful process exit as semantic success. Keep raw logs and classify only after review. Do not use agent-generated code to bypass verification or suppress diagnostics.
